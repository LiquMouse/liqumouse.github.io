## 问题的发生

使用VScode连接到WSL2时持续出现 `Error: WebSocket close with status code 1006`，反复重试均失败。

## 排查过程

### 首先检查 WSL2 本身

```powershell
wsl --version    # 2.7.10.0
wsl --status     # Ubuntu Running, WSL2
```

WSL2 运行正常，不是 WSL 本身的问题。

### 检查 VScode Server

在 WSL2 内查看日志:

```bash
cat ~/.vscode-server/data/logs/*/remoteagent.log
```

Server 启动正常，日志显示 "Extension host agent started"，没有崩溃。说明问题不在 Server 端，而在连接通道上。

### 检查 .wslconfig

查看 `C:\Users\<user>\.wslconfig`：

```ini
[wsl2]
localhostForwarding=true
networkingMode=Mirrored
firewall=false
```

`networkingMode=Mirrored` 是常见嫌疑——GitHub 多个 issue（[#261631](https://github.com/microsoft/vscode/issues/261631)）报告 Mirrored/VirtioProxy 模式导致 1006。修改为默认 NAT 模式并重启 WSL：

```powershell
wsl --shutdown
```

**无效。**

### 开启 debug 日志

在 VScode `settings.json` 中：

```json
"remote.WSL.debug": true
```

然后通过 `Ctrl+Shift+P` → `WSL: Show Log` 查看 WSL Daemon 日志。

或者直接找到日志文件：

```
C:\Users\<user>\AppData\Roaming\Code\logs\<session>\window1\exthost\ms-vscode-remote.remote-wsl\wsl-daemon-*.log
```

关键日志：

```
[07:32:17.629] WSL feature installed: false (dll path)
[07:32:18.102] Windows build: 9200.
[07:32:18.102] Starting VS Code Server inside WSL (wsl1)
```

Windows 版本号被识别为 **9200**（实际是 Windows 11 build 26200），导致 WSL 扩展误用 WSL1 兼容模式。

紧接着：

```
Exec (0) stderr: /home/liqumouse/.vscode-server/bin/.../node: cannot execute binary file
Exec (0) has terminated with status 126
```

Proxy 进程连续 10 次尝试启动均失败，每次返回 `cannot execute binary file`。

### 为什么是 9200？

在 WSL Daemon 日志的环境变量中发现了：

```
"__COMPAT_LAYER": "Win8RTM"
```

这导致 Windows 对 VScode 进程谎报系统版本为 Windows 8（9200）。

## 根因

VScode 的可执行文件被设置了 **Windows 8 兼容模式**。注册表中：

```
HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers
  C:\Users\...\Code.exe = ~ WIN8RTM
```

完整的因果链：

```
Code.exe 设置了 WIN8RTM 兼容模式
  → __COMPAT_LAYER=Win8RTM
    → Windows 报告版本号为 9200
      → WSL 扩展误判 WSL2 不可用
        → 使用 bash.exe（WSL1 兼容层）代替 wsl.exe
          → bash.exe 将 ELF node 二进制当 shell 脚本执行
            → cannot execute binary file (status 126)
              → TCP proxy 链路断裂
                → WebSocket 1006
```

这个问题与 `.wslconfig` 中的 `networkingMode`、Steam++ 代理、WSL2 内核版本等**均无关**——它们看起来可疑，但不是根因。

## 解决方案

删除 VScode 的兼容模式标志：

```powershell
Remove-ItemProperty "HKCU:\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers" -Name "C:\Users\<user>\AppData\Local\Programs\Microsoft VS Code\Code.exe" -Force
```

完全退出 VScode，重新打开，连接 WSL2 即可恢复正常。

## 教训

- **不要轻易给全局工具设置兼容模式。** 这个 `WIN8RTM` 可能是为了某个旧软件设置的，但被 Windows 匹配到了 VScode 上。
- **看到 `__COMPAT_LAYER` 环境变量时立刻警觉。** 这个变量会系统性地影响所有子进程的 Windows API 返回值。
- **WebSocket 1006 只是症状，不是根因。** 1006 = 连接被异常关闭，可能的原因从网络层到应用层都有。关键是在 debug 日志中找到链路上真正断裂的那一环。
